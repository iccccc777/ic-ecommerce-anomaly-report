## 抽样方法

本次采用用户级随机抽样，而不是逐行抽样：

1. 对每个 `user_id` 计算稳定哈希：`zlib.crc32(str(user_id).encode("utf-8")) % 10000`。
2. 当哈希值 `< 200` 时保留该用户，即约 2% 用户。
3. 保留这些用户的全部行为记录。

结果：

| 项目 | 值 |
|---|---|
| 抽样用户数 | 19,476 |
| 抽样行为行数 | 1,966,733 |
| 清洗后行为行数 | 1,965,596 |
| 抽样文件 | `data/UserBehavior_sample.csv` |
| 抽样文件 SHA256 | `F67CF88FD3564E21576848E989890A3809C7633FEA82EEBA246376A6B531822D` |

## 为什么用用户级抽样

行级抽样会让同一个用户的连续行为被打散，导致“新用户”“回归用户”“留存”等用户口径失真。例如旧版每 50 行抽 1 行时，12 月 2 日出现大量“新用户”，实际是行级抽样造成的假象。用户级抽样保留每个用户完整行为序列，用户类指标更可靠。

## 如何复现

保持 `data/UserBehavior_raw.csv` 不变，运行：

```powershell
python python\02_build_sqlite.py
```

脚本会重建 `UserBehavior_sample.csv` 和 `data/ecommerce.db`。

## 已知局限

- 数据集只有 9 天窗口，`first_day` 是“窗口内首次出现日”，不是用户真实注册日；留存和“新用户”口径受窗口左截断影响。
- 用户级抽样比例只有约 2%，单日 DAU 在 1.4 万到 1.9 万量级；用于观察趋势和归因足够，但小类目、小留存群体的波动需要谨慎解释。
- 数据没有价格和订单金额，GMV、客单价无法直接计算。
