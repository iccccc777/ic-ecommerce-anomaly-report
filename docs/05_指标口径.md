# 指标口径

当前淘宝行为数据集没有商品价格，也没有订单金额字段，因此不能直接算真实 GMV、客单价、支付金额。

在报告中要明确写：

> 本数据集只有行为事件，因此使用 `buy` 行为次数作为购买量的代理指标；GMV、客单价等金额类指标需要后续补充价格数据。

## 核心指标定义

| 指标 | 口径 |
|---|---|
| DAU | 当天有任意行为的去重用户数 |
| PV | 当天 `pv` 行为次数 |
| 加购 | 当天 `cart` 行为次数 |
| 收藏 | 当天 `fav` 行为次数 |
| 购买 | 当天 `buy` 行为次数 |
| 购买转化率 | `buy / pv` |
| 加购转化率 | `cart / pv` |
| 收藏转化率 | `fav / pv` |
| 人均购买次数 | `buy / DAU` |

## 后续需要补充的指标

- GMV：需要商品价格或订单金额表
- 客单价：需要金额和购买用户/订单数
- MAU：需要完整 30 天跨度数据；当前样本主要覆盖 2017-09 到 2017-12
- 留存：需要按用户首次活跃日分组

## 为什么先写口径

面试和报告中最重要的不是“算出了多少”，而是“你定义的 DAU、转化率是什么”。口径写清楚，才能防止别人质疑你的数字不可复现。

## 本次分析的数据清洗口径

- 业务时间窗口：2017-11-25 到 2017-12-03，按北京时间计算。
- 时间戳处理：SQLite 中使用 `date(timestamps, 'unixepoch', '+8 hours')`。
- 脏数据处理：原始时间戳中混有异常值，因此只保留上述窗口内的记录。
- 后续所有指标统一从 `behavior_clean` 视图读取，保证口径一致。

## 抽样口径

- 采用用户级抽样：按 `user_id` 稳定哈希保留约 2% 用户，共 19,476 个用户、196.7 万行。
- 单日 DAU 量级为 1.4 万到 1.9 万；指标不能直接外推全量。
- 当前 `funnel.csv` 是窗口期内用户行为重叠率，不是严格的行为顺序漏斗；严格漏斗需要按用户行为时间序列重新计算。
- 数据只有 9 天，未单独计算 MAU；GMV、客单价因缺少价格和订单金额无法计算。
