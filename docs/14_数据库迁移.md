# 数据库迁移：SQLite 到 MySQL 8

## 1. 目标

当前项目原先使用 SQLite，适合本地开发和单机复现，但面试岗位通常更关注 MySQL/PostgreSQL、索引、批量导入和方言差异。

本次补强完成：

- 将 SQLite 行为抽样迁移到 MySQL 8。
- 用 MySQL 方言重写日指标、窗口期用户重叠率、留存和归因 SQL。
- 使用复合索引优化批量导入和查询。
- 对比 MySQL 结果与原 `outputs/*.csv` 基线。
- 提供 PostgreSQL 等价脚本，作为跨数据库迁移能力展示。

## 3. MySQL 运行方式

先在 `.env` 中配置连接信息：

```text
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=your-password
MYSQL_DATABASE=ic_ecommerce
```

执行迁移：

```powershell
.\.venv\Scripts\python.exe python\09_migrate_to_mysql.py --recreate
```

默认行为：

1. 读取 `data/ecommerce.db` 的 `behavior` 表。
2. 创建 MySQL 数据库和表。
3. 将行为数据导出为临时 TSV。
4. 使用 `LOAD DATA LOCAL INFILE` 批量导入。
5. 导入完成后创建二级查询索引。
6. 重算用户、商品和类目维表。
7. 运行方言查询并写入 `outputs/mysql/`。

MySQL 服务需要开启：

```sql
SHOW VARIABLES LIKE 'local_infile';
```

结果应为 `ON`。

## 5. 方言差异

### 日期和时间

SQLite：

```sql
date(timestamps, 'unixepoch', '+8 hours')
```

MySQL：

```sql
DATE_FORMAT(
    DATE_ADD(
        FROM_UNIXTIME(
            timestamps - TIMESTAMPDIFF(SECOND, UTC_TIMESTAMP(), NOW())
        ),
        INTERVAL 8 HOUR
    ),
    '%Y-%m-%d'
)
```

迁移连接仍会设置为 UTC，但视图不再依赖会话时区。核心思路是先把时间戳换算回 UTC，再加 8 小时：

```sql
DATE_ADD(
    FROM_UNIXTIME(
        timestamps - TIMESTAMPDIFF(SECOND, UTC_TIMESTAMP(), NOW())
    ),
    INTERVAL 8 HOUR
)
```

因此无论会话处于 UTC、北京时间或其他时区，`event_day` 和 `event_hour` 都保持一致。

### 整数除法

MySQL 整数除法默认精度不足。所有比率都显式转换为 `DECIMAL(20, 10)`：

```sql
ROUND(
    CAST(numerator AS DECIMAL(20, 10)) / NULLIF(denominator, 0),
    6
)
```

### 建索引顺序

迁移百万级数据时，先建表并导入，再创建二级索引，比导入前建全部索引更快。`08_indexes.sql` 包含：

- `(behavior_type, user_id)`：窗口期行为用户去重。
- `(category_id, user_id)`：类目用户去重。
- `(item_id, user_id)`：商品用户去重。
- `(user_id, timestamps)`：用户行为序列。
- `(timestamps)`：窗口过滤。

### 用户增量拆解

MySQL 8.0.46 对 `INTERSECT` CTE 在 `UNION` 中重复引用的优化存在异常，可能把流失用户错误计算为 0。

迁移版改为对用户做条件聚合：

```sql
MAX(CASE WHEN day = '2017-12-01' THEN 1 ELSE 0 END) AS active_1201
MAX(CASE WHEN day = '2017-12-02' THEN 1 ELSE 0 END) AS active_1202
```

再按 `active_1201` 和 `active_1202` 分类。该写法在 MySQL 和 PostgreSQL 中语义一致，也避免了重复扫描。

## 6. PostgreSQL

PostgreSQL 脚本位于 `sql/postgresql/`，日期口径使用：

```sql
TO_CHAR(
    TO_TIMESTAMP(timestamps::DOUBLE PRECISION)
        AT TIME ZONE 'Asia/Shanghai',
    'YYYY-MM-DD'
)
```

当前机器未运行 PostgreSQL，所以 PostgreSQL 部分完成：

- 方言重写。
- 禁止 SQLite 专属函数的静态测试。
- 与 MySQL 相同的业务字段和查询结构。

未完成 PostgreSQL 实例级运行验证，文档中不会声称已真实跑通 PostgreSQL。

## 7. 当前局限

- MySQL 迁移使用约 2% 用户级抽样，不是 100,150,807 行全量数据。
- `LOAD DATA LOCAL INFILE` 要求客户端和服务端都允许本地文件导入。
- 迁移耗时受本机磁盘、索引和 MySQL 缓存影响。
- 本地 Windows 环境未安装 PostgreSQL，因此本地执行静态检查；GitHub Actions 会启动 PostgreSQL 16 并运行实例级集成测试。
